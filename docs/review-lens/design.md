# 视觉设计

> 本文档仅在含前端界面的产品中产出（Web/前端，或组合含前端）。处理"长什么样、怎么操作"。
> 非前端形态（BFF/API、CLI、库/SDK）的对外接触面契约在 architecture.md 中定义。

## 1. 信息架构

产品没有自己的"页面"，全部界面寄生在 GitLab MR 讨论页上，只有三个接触面：

```
GitLab MR 讨论页（宿主）
├── 每条代码评论旁：解读入口（28px 按钮，唯一注入到宿主排版里的东西）
└── 右侧抽屉（唤起后）
    ├── 顶栏     方法名 · 文件名 · 关闭
    ├── 评论卡   作者 / 时间 / 正文（正文里的标识符是可点 chip）
    ├── 回复串   该主题下的后续回复，按时间顺序；「后来怎么改」常写在这里
    ├── 时间脊   THEN 谁在何时评论  ←→  NOW 谁在何时修正
    ├── 代码区   评论时版本 ↕ 修正后版本（唯一滚动区）
    └── 底栏     评论间导航 · 视图切换 · 展开方法体 · 相关行 · 存为卡片

扩展工具栏弹窗（独立入口）
├── 筛选条     全部 / 按仓库
├── 卡片列表   方法名 · 笔记 · 双时点缩略 · 操作
└── 底栏       本地存储说明 · 导出 Markdown
```

层级只有两层：**一条评论 → 它的前后两态**。信息架构上刻意不做树、不做多标签页——产品的全部价值是把两个时点摆在一起，多一层导航就多一次分心。

## 2. 视觉风格

| 项        | 内容                                                                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 美学方向  | **教科书**：明亮、圆角偏大、字号偏舒展，读起来像一本讲评审的教材而不是终端工具。理由是使用者在学习，界面语气该轻；同时保留"时间对照"这条主线                                                                              |
| 配色      | `head-bg #EEF1FB` 浅蓝灰顶栏、`paper #F4F6FC` 抽屉底、`card #FFFFFF`、`line #E4E8F2`、正文 `#2F3A52`、`then #A8710F` 琥珀（旧/评论时，底 `#FEF6E3`）、`now #147B5C` 青瓷（新/修正后，底 `#E7F7EF`）、`mark #4F46E5` indigo（锚点、标识符、主按钮） |
| 字体      | 界面：系统 UI 栈（不引任何 webfont，扩展跑在内网、不该外链）；代码：`ui-monospace / SFMono / Menlo`，13px / 1.8。元信息用 UI 字体的中文小字（"评论时" / "修正后"），不用大写 mono                                             |
| 动效基调  | 近乎无：只有抽屉滑入、hover 变色、跳转时目标行短暂闪一下。宿主页是别人的页面，动效越少越像原生功能                                                                                                                       |
| 参考/灵感 | 教材里的"错例 / 正例"对照页；indigo 主色刻意与 GitLab 自身的蓝拉开距离，避免看起来像 GitLab 的原生功能却行为不一致                                                                                                        |

配色不是随便挑的强调色，而是一套**贯穿全局的语义**：琥珀恒等于"旧/评论时"，青瓷恒等于"新/修正后"，indigo 恒等于"评论指向这里"。

**徽标不参与这套语义**，用中性灰蓝（DD-41）。琥珀/青瓷在代码区之所以无歧义，是因为它对应**空间位置**：上/左是评论时，下/右是当前。徽标没有位置，硬套颜色就会有两种都说得通的读法——「评论后代码已改动」既可以理解成"这条评论过时了"（旧→琥珀），也可以理解成"代码变新了"（新→青瓷）。一个需要解释才能说清指向谁的颜色不传达信息，只会稀释琥珀/青瓷本来的空间含义。三种文案照旧：

| 比较结果 | 徽标文案 |
| --- | --- |
| 评论之后代码改过 | 评论后代码已改动 |
| 至今没人碰过 | 至今未改动 |
| 当前分支上找不到 | 代码已不在当前分支 |因此 diff 的增删也用琥珀/青瓷而不是通用红绿——同一件事只有一套颜色，读者不必学两套，顺带避开红绿色盲，也不与 GitLab 自身的 diff 配色混淆。两个语义色刻意保持低饱和：它们要当整行底色铺在代码下面，饱和度一高代码就读不清了。

**为什么不用深色顶栏**：初版用 ink `#1B2430` 深顶栏是为了让浮层与 GitLab 白页面有边界，但深顶栏 + 深实底按钮 + 大写 mono 标签三样叠起来读成"终端/极客"，与学习者的语气不合。浅蓝灰顶栏在保留边界感的同时退掉了这层重量（三套配色的对照见 `designs/theme-options.html`）。

## 3. 页面结构与导航

| 页面/接触面    | 路由                            | 功能说明                                   | 所属模块 |
| -------------- | ------------------------------- | ------------------------------------------ | -------- |
| 解读入口       | 注入宿主页每条代码评论          | 唤起抽屉，是产品唯一的入口                 | M1       |
| 抽屉 · 主态    | 宿主页内浮层                    | 评论 + 前后两态代码对比                    | M1 / M2  |
| 抽屉 · 相关行  | 抽屉内浮层                      | 评论真正所指的候选行                       | M3       |
| 抽屉 · 未改动  | 主态的右栏变体                  | 这处至今没被改过                           | M2       |
| 抽屉 · 失败    | 主态的整区变体                  | 取数失败的原因与出路                       | M1       |

| 弹窗 · 空态    | `popup.html`                    | 引导去 GitLab 点第一条"解读"               | M4       |

## 4. 各页面设计

### 4.1 解读入口

- **功能说明**：在每条代码评论旁提供唤起抽屉的按钮。
- **布局说明**：28px 高、与 GitLab 自身 icon button 同尺寸，挂在评论行右侧、`align-self: start`，不改变宿主页行高与列宽。按钮左侧一根 3px 的琥珀→青瓷渐变小竖条，是全产品唯一的品牌标记。
- **交互说明**：hover 转 indigo 底 / 点击打开抽屉并高亮该评论 / 抽屉已开时再点另一条评论直接换内容不重开。
- **设计产物**：`designs/drawer.html`（宿主页仿真区）
- **对应验收标准**：V-1、V-16

### 4.2 抽屉 · 主态（前后两态对比）

- **功能说明**：产品主界面。上半是评论，下半是评论时版本与修正后版本的对照。
- **布局说明**：右侧固定浮层，默认宽 `min(820px, 52vw)`，左边缘可拖拽调宽。竖向自上而下：浅蓝灰顶栏 → 白色评论卡 →（有回复时）回复串 → 时间脊标签行 → 代码区（唯一滚动区，`max-height` 收住，内容少时下方留 paper 底而不是白洞）→ 白色底栏。代码区两种视图：**上下堆叠（默认）**每栏拿全宽、长 Java 行基本不折行；**并排两栏**用于窄行代码或需要严格左右对照时。两栏/两段之间是时间脊：并排时是竖向的琥珀→青瓷渐变；上下堆叠时改成 8px 的两色硬分割，因为同一条渐变横向铺到 780px 以上会被过渡色摊淡到看不见。
- **交互说明**：视图切换（并排/上下，记住选择）/ 两栏滚动同步 / 点评论正文里的标识符跳到代码中对应位置并闪一下 / 展开完整方法体 / 底栏在同一 MR 的评论间前后走 / **点抽屉以外的任意位置关闭**、`Esc` 关闭、点 ✕ 关闭。
- **设计产物**：`designs/drawer.html`；核对截图 `designs/shots/drawer-stacked.png`（上下，默认）、`designs/shots/drawer-side.png`（并排）
- **对应验收标准**：V-2、V-3、V-5、V-6、V-8、V-10

回复串紧跟在首条评论下方，但必须**读得出层级**：首条评论在白卡上，带作者、日期与（评论写在旧版本上时）一枚琥珀色「旧版本差异」徽标；回复区换到 paper 底色，顶上一行 `回复 · N 条` 的 mono 小字，每条回复带左侧 2px 竖线并缩进。只有一条评论时整个回复区不渲染，不留空槽。

这一版是真机试用改出来的：初版首条评论只显示作者名、回复显示名字加日期，两块并列没有任何层级，使用者根本认不出哪条是回复（反馈原话「没看到回复」）。徽标用琥珀是因为它与代码区「评论时」那一侧是同一个语义色——同一件事只有一套颜色（DD-2）。

代码区的三个视觉通道互不覆盖，叠在同一行也读得清：

| 通道     | 表现                     | 含义                     |
| -------- | ------------------------ | ------------------------ |
| 行底色   | 琥珀底 / 青瓷底          | 该行被删 / 被加           |
| 左侧竖脊 | indigo 3px + 行号加粗变色 | 评论锚定在这一行          |
| 行内框   | indigo 虚线框            | 评论真正所指的行（M3 推断） |

### 4.3 抽屉 · 未改动变体

- **功能说明**：评论所指的代码至今没被改过时，右侧不能伪造一个 diff。
- **布局说明**：右栏（或下段）换成居中空态：结论一行加粗、依据一句（"评论之后的 12 个 commit 都没有碰过这几行"）、一个出口按钮。
- **交互说明**：点"在 GitLab 打开最新版本"新开标签页到当前 master 的该文件行。
- **设计产物**：`designs/drawer.html`（状态：至今未改动）；截图 `designs/shots/drawer-untouched.png`（该图摄于时间脊标签中文化之前，图中标签仍是 `then` / `now`，原型内已是"评论时" / "修正后"）
- **对应验收标准**：V-7

### 4.4 抽屉 · 失败变体

- **功能说明**：取不到代码时说清发生了什么、下一步做什么。
- **布局说明**：代码区整体换成居中失败块：mono 小字的机器原因（`401 · 登录态已失效`）、一句人话标题、一段说明、三个动作。失败态隐藏时间脊——没有两个时点可谈。
- **交互说明**：重试（不关抽屉）/ 去 GitLab 登录（新标签页）/ 配置访问令牌（打开设置）。
- **设计产物**：`designs/drawer.html`（状态：取数失败）；截图 `designs/shots/drawer-failure.png`
- **对应验收标准**：V-4、V-14

### 4.5 抽屉 · 相关行浮层

- **功能说明**：评论锚在问题代码的上方或下方时，给出它可能真正指的行。
- **布局说明**：底栏上方的 340px 浮层，每项三行：行号（indigo mono）、代码单行截断、命中依据一句。
- **交互说明**：点某项滚到该行并加虚线框 / 点外部关闭。
- **设计产物**：`designs/drawer.html`（状态：相关行浮层）
- **对应验收标准**：V-9

### 4.6 弹窗 · 卡片列表与空态

- **功能说明**：管理攒下的学习卡片并导出。
- **布局说明**：400×560，浅蓝灰顶栏（品牌 + 计数）→ 横向滚动筛选条（按仓库）→ 卡片列表（唯一滚动区）→ 底栏（本地存储说明 + 导出）。每张卡片：方法名 + 仓库文件、笔记两行、**双时点缩略**（左琥珀 then / 右青瓷 now，各一行截断代码，与抽屉同一套语义色）、操作行。空态用一段琥珀→青瓷小色条代替插画，一句结论加一句去哪儿做。
- **交互说明**：筛选切换 / 回到 MR（回跳并自动开抽屉）/ 编辑笔记（原地）/ 删除 / 导出 Markdown。
- **设计产物**：`designs/popup.html`；截图 `designs/shots/popup.png`
- **对应验收标准**：V-11、V-12、V-13

| 组件           | 用途                                       | 使用页面           |
| -------------- | ------------------------------------------ | ------------------ |
| 时间脊         | 把两个时点绑起来（签名元素）：并排为竖向渐变，堆叠为两色硬分割 | 抽屉主态、弹窗空态 |

| 按钮           | 次要（白底细框）/ 主要（ink 实底）           | 全部               |

## 6. 设计决策

> 编号规则：DD = Design Decision（设计决策），如 DD-1、DD-2

| 编号  | 决策                                                       | 理由                                                                                                                       |
| ----- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| DD-1  | 签名元素是"时间脊"，全部视觉张力只花在它身上                | 产品唯一的信息价值是两个时点的对照，把它做成看得见的轴；其余一律安静，避免在别人的页面上喧哗                                 |
| DD-2  | 旧=琥珀、新=青瓷，diff 增删复用同一对颜色，不用通用红绿      | 同一语义只留一套颜色，读者不必学两套；顺带避开红绿色盲，也不与 GitLab 自身的 diff 配色混淆                                    |
| DD-3  | 锚点行走"左竖脊"通道，diff 走"行底色"通道，相关行走"虚线框"   | 三者会叠在同一行，占用不同视觉通道才不会互相盖掉                                                                            |
| DD-4  | **默认上下堆叠，并排作为可切换视图**                        | 实测（1600px 屏、820px 抽屉）并排每栏只剩约 40 字符，Java 行普遍 60–100 字符，几乎每行折行；上下堆叠每栏全宽后基本零折行      |
| DD-5  | 代码长行用软换行 + 悬挂缩进，不用横向滚动                    | 横向滚动在两栏里要滚两次且破坏同步；悬挂缩进让续行一眼看出属于上一行                                                        |
| DD-6  | 抽屉宽度默认 52vw 且可拖拽、记住                            | 宽度直接决定折行多少，是读代码的核心变量，不该由我替用户定死                                                                |
| DD-7  | 抽屉底栏放"上一条/下一条评论"导航                           | 抽屉会遮住宿主页右半，用户不该为切换评论去关抽屉；顺带让"逐条读完一个 MR"成为顺手动作                                       |
| DD-8  | 不引入任何 webfont、不引图标字体，图标用 CSS 与 Unicode      | 内网环境不该外链资源；也避免与宿主页字体加载竞争                                                                            |
| DD-9  | 品牌标记只有一处：入口按钮上 3px 的琥珀→青瓷竖条              | 注入别人的页面要克制，一个色条足够被认出，不放 logo 不放名字                                                                |
| DD-10 | 失败与空态都是"机器原因 + 人话结论 + 出路"三段               | 学习工具的失败不该只说"加载失败"；把 401 这类原因直接摊开，用户自己就知道去登录                                              |
| DD-12 | 配色定为「教科书」（浅蓝灰顶栏 + indigo 主色 + 中文小字标签），不用初版的深 ink 顶栏 | 深顶栏、深实底按钮、大写 mono 标签三样叠起来是终端味，与学习者的语气不合；其中标签样式本就没有功能理由。浅蓝灰顶栏保留了浮层与宿主页的边界，indigo 与 GitLab 自身的蓝有区分度，不会被误认成原生功能 |
| DD-13 | 上下堆叠态的时间脊用两色硬分割 + 8px 厚度，不用渐变 | 渐变横向铺开后中段全是过渡色，实测在 785px 宽、6px 高时几乎不可辨；语义只有「这边是旧、那边是新」，硬分割就够 |
| DD-41 | 徽标用中性灰蓝，不参与琥珀/青瓷语义（撤回 DD-40） | 琥珀/青瓷的无歧义性来自空间位置（上下、左右）；徽标没有位置，同一句话有两种都成立的读法，颜色因此传达不了信息 |
| DD-42 | diff 的基准固定为两侧的方法体，扩展出来的上下文行永不标记改动 | 此前 diff 是对"当前可见的那两段"做的，于是按「多看 10 行」时同一行的着色结论会变——着色必须是这段代码的客观事实，不能随视口变 |
| DD-43 | 定位不到时给出「评论之后谁改过这个文件」的 commit 线索 | 作者回复「删了」时，「找不到」其实是正确结论，但写成技术性失败等于把死胡同摆给读者；读者真正想知道的是"她到底怎么改的" |
| DD-44 | 评论与回复正文里的截图就地渲染，但只认宿主同源的 `/uploads/` 附件；外站图片保留原始 Markdown 文本 | 评审里「改成这种」往往就是一张截图，正文只剩一行 `![image](…)` 时这条回复等于没有内容。外站图片不自动加载：正文是他人可写的内容，自动取第三方资源会把"谁在什么时候读了这条评论"发出去 |
| DD-45 | 「评论后代码已改动」的判据是这段方法两侧真有差异，不是 `thread.outdated` | `outdated` 只说明 MR 有了新版本——后续提交可能改的是文件别处甚至别的文件，这段方法逐行未变。判据必须与代码区的着色、说明行的「N 行有改动」同源，否则界面会自己打自己：两侧一模一样却挂着"已改动" |
| DD-46 | 相关行浮层里的行号与说明文字基线对齐 | 行号用 mono、说明用 UI 字体，两种字体的基线与行高不同；grid 默认拉伸对齐时数字看着就是没对齐，说明折成两行时更明显 |
| DD-47 | 切换同步滚动不重绘（监听常驻、回调里读开关），切换视图按滚动比例还原位置 | 读者已经把两侧滚到要看的那一段了，切个开关却整棵重建、位置归零，屏幕上就是"闪一下跳回开头"。同步开关根本不改布局，重绘是纯浪费；视图切换必须重排，但可以把位置还原回去。换布局后列宽变了、折行数也变了，像素值不再等价，所以按比例而不是按像素还原 |
| DD-48 | 两侧逐行相同时右侧不重复展示代码，只给一句结论；对比专用控件（视图切换、同步滚动）只在真有两侧可对照时渲染（修正 DD-45 的下半截） | 我原以为「右侧照旧展示当前版本、确认它真的没变」本身就是答案，真机上看那只是把同一段代码抄第二遍，占双倍篇幅、还让一整排对比控件空转。用户直接问「代码未改动，为什么会有修正后」。同理 untouched / unlocatable 只有一句结论时，切视图与同步滚动也是按了没反应的死控件 |
| DD-49 | 判别态按「读者需要区分的结果」分，不按「我怎么算出来的」分：identical 与 untouched 合并为 unchanged，共 3 态 | 两者对读者是同一个结论——这段代码还是评论时那样、评论提的问题现在仍然成立；区别只在一个由 outdated 判出、一个由逐行 diff 判出，那是实现细节。分成两态的代价是 7 条文案说同一件事（2 个徽标 + 2 个标题 + 3 句详情），读者要自己归纳它们是不是一个意思。合并后依据只剩一处口径：评论之后动过这个文件的提交数 |
| DD-50 | 视图切换始终提供（它排的是「两个块」，右边那个块是代码还是结论都一样）；只有同步滚动依赖「两个可滚动的代码区」（收窄 DD-48） | 上一轮用一个判据把两个控件一并隐藏是错的：它们成立条件不同。切换消失后读者只会觉得功能丢了——用户原话「为什么现在不支持左右和上下 2 种模式了」。单栏时并排=代码在左、结论在右，上下=代码在上、结论在下，两种都成立，`.panes` 的 grid 本来就同时管这两个块 |
| DD-51 | 结论文案不提方位（不说「左边」「上面」） | 布局可切，方位就不是固定事实；结论块紧挨着代码，本来也不需要指路。这条与 DD-18「带空间含义的标签只在对应布局下渲染」同源 |
| DD-39 | 两种视图都提供「同步滚动」开关，默认开 | 同步的意义是让两侧始终停在对应的那段代码上，这在上下布局里同样成立。此前以「上下时一动两边齐动反直觉」为由只给并排，判断过于绝对 |
| DD-40 | 评论徽标覆盖三种比较结果，颜色跟着它描述的对象走 | 徽标此前只有「评论后代码已改动」一种文案，另两种结果没有任何提示。颜色语义与代码区一致：琥珀=评论时那侧、青瓷=当前那侧、灰=两侧都谈不上 |
| DD-37 | 相关行浮层锚在触发它的按钮正上方，而不是固定在底栏右侧 | 浮层与触发点错开会让人找不到因果——点左边的按钮、右边弹出来一块 |
| DD-38 | 时间脊右侧不再挂「当前分支」标签 | pane 头部已经写了「修正后」，右上角再来一个是同一信息第三次出现；DD-24 本该一并删掉，上一轮只删了左侧 |
| DD-34 | 定位不到对应代码时，右侧不展示任何代码，只说明「找不到对应位置」并给出口 | 展示一段无关代码比什么都不展示更糟——它看起来像是对的。此前算出了 `drifted` 标记却没用上，等于把错误藏起来 |
| DD-35 | 取消「片段 / 整段」二态切换，改为「按方法展示 + 上下各多看 N 行」的单调扩展 | 二态开关把两个正交的东西（窗口大小、方法边界）塞进一个按钮，于是出现「展开全部反而更少」；单调扩展永远只增不减，不会自相矛盾 |
| DD-36 | 设置页去掉白卡片与大圆角，说明文字降为输入框下方的小字 | 大段说明比输入框还抢眼，视觉重量全压在文字上；表单该让人一眼看到"要填什么"，解释退到次要位置 |
| DD-33 | 工具栏图标分彩色/灰度两套，默认灰色，只在插件真正生效的页面点亮 | 图标一直亮着等于骗人；判据不用 URL 匹配而是「content script 是否在这一页真的挂载成功」，因此「是 GitLab 但不是 MR 页」也会灰——反映的是"这里能不能用"而不是"域名对不对" |
| DD-29 | 代码做 Java 语法着色（关键字/字符串/注释/数字/类型名） | 这个产品的主体内容是代码，通篇纯黑本身就是阅读障碍；着色分两层——语法着色管"这是什么"，diff 底色管"这里变了"，互不干扰 |
| DD-30 | 上下堆叠时两侧各自独立滚动；只有并排才同步，且同步可关 | 上下排列时"一动两边齐动"完全反直觉；并排时同步有用但两侧行数不同也会错位，所以给一个开关而不是写死 |
| DD-31 | 措辞去掉实现术语：「旧版本差异」→「评论后代码已改动」，「展开完整方法体」→「展开全部 N 行 / 收起」 | 前者是照抄 GitLab 的说法，脱离上下文不知所云；后者在讲实现细节（方法体），读者只想知道会多看到多少 |
| DD-32 | 代码区上方常驻一行状态说明：在看哪个方法、范围多少行、有几行改动 | 反馈「要展示的内容还是不太清楚你的选择逻辑」——选择逻辑不该靠猜，直接写出来 |
| DD-27 | 设置页内容收进居中的卡片（最大 640px），字段各自成块 | 它是一个整页标签页，内容贴在左上角、右边空一大片会显得像没加载完；居中卡片是标签页里最省心也最像"设置"的形态 |
| DD-28 | 弹窗空态不渲染筛选条与导出按钮 | 0 张卡片时「全部 0」与「导出 Markdown」都是按了没反应的死控件；空态只该留一句结论加一句怎么做 |
| DD-22 | 琥珀/青瓷只上在真正变了的行上，pane 头部保留色标与分隔线 | 反馈「代码着色这么多，不知道看什么」的真实根因不是配色，而是左右两侧配错了方法（行号漂移，见 DD-26），于是几乎每行都被标成差异、整片染色。定位修对之后着色自然收敛；这里只保留头部色标与一条分隔线，不再给整块加底 |
| DD-26 | 修正后一侧的锚点按方法签名重新定位，不沿用评论时的行号 | 文件改过之后行号会漂移；真机上评论锚在旧版 32 行，当前版 32 行已落到构造函数里，右半屏展示了完全不相干的代码。靠签名而不是靠锚点行文本定位，因为被评论的那行往往正是被改掉的那行 |
| DD-23 | 默认展示锚点所在的完整方法（超过 60 行才退回锚点 ±10 行） | 评论要读懂得看清这段代码在干什么；只给锚点上下 6 行经常连方法签名都看不到 |
| DD-24 | 去掉时间脊的左右标签，只留视图切换 | 作者与日期在评论卡里已有、「评论时/修正后」在 pane 头部已有，同一信息第三次出现只是占地方 |
| DD-25 | 抽屉打开时锁住宿主页滚动，关闭时精确还原 | 抽屉是当前焦点，背后的页面跟着滚会让人不知道自己在看哪儿；还原时按保存的原值写回，不留下自己的痕迹 |
| DD-17 | 抽屉左边缘可拖拽调宽并记住宽度 | 宽度直接决定长 Java 行折不折行，是读代码的核心变量（DD-6 早已如此决定，此前只落在文档里没实现）|
| DD-18 | 上下堆叠时不渲染右侧「修正后 · 当前分支」标签 | 左右分列的标签是为并排设计的；上下堆叠时右上角出现「修正后」既与位置矛盾，又和 pane 头部重复 |
| DD-19 | 回复区改白底 + 左侧竖线，把 paper 底留给下方对比区 | 回复区原用 paper 底，与下方对比区同色、连成一片；层级要靠「白 → 白带竖线 → paper」三层递进，而不是两处同色 |
| DD-20 | 代码字号 13px → 14px，行高 1.8 | 这个产品的主体内容就是代码，字号该给足；比 GitLab 自身的 diff 略大是有意的——读者是来精读一处的，不是来扫全文的 |
| DD-21 | 弹窗高度随内容伸缩（min 320 / max 560），不写死 | 空态时写死 560px 会留出大半屏空白，看起来像没加载完 |
| DD-16 | 回复区换底色 + 小标题 + 左侧竖线缩进，首条评论加日期与「旧版本差异」徽标 | 真机反馈「没看到回复」——回复其实渲染了，但与首条评论视觉等价，读者无从分辨。层级靠三件事建立：底色区分区块、标题声明关系、竖线表达从属 |
| DD-14 | 抽屉展示整条主题的回复，而不只是首条评论 | 真机试用暴露的问题：评论者提问、作者回一句「加了 Optional.ofNullable(...)」，这句就是「后来怎么改」的人话结论。只显示首条等于把答案藏在 GitLab 的折叠里，而本产品存在的理由正是把答案摊开 |
| DD-15 | 点抽屉以外任意位置即关闭，与 `Esc`、✕ 并存 | 读评审是快速翻阅的动作，关闭不该要求瞄准某个按钮；三条关闭路径都留着，肌肉记忆不同的人都不会卡住 |
| DD-11 | 弹窗卡片带双时点缩略行，不只列标题                          | 复习时靠"前 → 后"两行代码就能回忆起整条评审，点开的成本省掉                                                                  |

## 7. 设计约束

- 界面寄生在宿主页里：注入点只有"评论旁的按钮"与"右侧浮层"两处，不改宿主页的既有 DOM 结构与全局状态（对应 V-15）。
- 抽屉的样式必须与宿主页隔离（实现层用 Shadow DOM 或强命名空间，在 architecture.md 定），GitLab 自身样式改动不应让抽屉变形。
- 不遮挡宿主页的评论输入框与主操作区；抽屉可关闭、可拖窄。
- 代码区是唯一滚动区，抽屉整体不出现双滚动条。
- 键盘可达：入口按钮、抽屉内所有操作可 Tab 到并有可见焦点圈；`Esc` 关闭抽屉。
- 中英文 GitLab 界面下都要能挂载，抽屉自身文案为中文（使用者是中文开发者，不做 i18n）。
- `prefers-reduced-motion` 下取消抽屉滑入与跳转闪烁。
- 原型里的代码、commit 号、人名取自用户提供的真实评审截图（`BuyoutSettleMentService.java`），其中 commit 短号与部分上下文行为示意值，实现阶段一律取真实数据。
