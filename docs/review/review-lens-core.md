## 结论

`core/` 的分层是干净的：15 个文件只在 `core/` 内部互相 import、没有反向依赖上层（`ui/`、`popup/`、`content/`、`background.js`），没有 barrel、没有 `export default`、没有 `console`、没有失效的 lint 指令、没有游离 Promise、没有 `var` / `==` / 参数重新赋值。注释密度高且绝大多数在讲「为什么」，这一点明显好于同类代码。

本批未发现 🔴 阻断项。47 条违规中有两类是全项目一致的系统性写法，占了近三分之一：**函数签名里直接解构入参**（8 处、6 个文件）与**自造布尔字段/变量不带 `is` 前缀**（`syncScroll`、`outdated`、`wholeMethod`、`fits`、`worthIt`、`tokenAccepted`、`ok`）。这两类改起来机械但会动到跨端字段名（`outdated`、`ok`）与已落盘的设置键（`syncScroll`、`drawerWidth`），建议与存储迁移一并规划，不要零散改。

最该先处理的是三条能直接减少误导的：`compare.js:48` `diffOfBase` 的前两个参数从来没被用过（调用处还在传两个大数组）；`locate.js:18` 与 `snapshot.js:59` 把同一段「从签名取方法名」的正则各写了一遍，而 `locate.js` 本来就 import 了 `snapshot.js`；`register-origin.js:53、55` 两处 `.catch(() => {})` 把取消注册的失败整个吞掉，用户以为站点已移除。

**建议先接入 lint。** 本报告里「未使用参数」「`||` 当默认值」「布尔命名」「注释形态」「同一前缀重复点号」这几类本应由机器一次性给全，靠人扫 1044 行必然有漏。零依赖的前提下也可以只装 eslint 一个 devDependency 跑 CI，不影响扩展本身仍然无构建、可直接加载。
